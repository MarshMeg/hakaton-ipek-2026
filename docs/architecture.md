# Архитектура «Ӟеч-а бур-а удмурт кыл?»

```
Android (Flutter)
  InAppWebView ── GET https://hakaton.marshmeg.ru/… ──▶ shouldInterceptRequest
        │                                                   │ есть в снимке?
        │                                                   ├─ да → ответ из снимка (assets APK
        │                                                   │       или скачанное обновление)
        │                                                   └─ нет, или /api/, /admin/ → сеть
        │ JS-мост (bridge.dart): backup/restore сохранения, уведомления, геолокация, share
        ▼
  Alpine.js: вход, игры и статистика, сохранение в localStorage (static/js/app.js, games.js)
        │  /api/signup, /api/login, /api/save  (только когда есть сеть)
        ▼
web: Django + gunicorn ── страницы, /content.json, /bundle/ (снимок для обновлений), /admin
        │ ORM                          │ django-storages
        ▼                              ▼
   PostgreSQL                       MinIO (S3) ── картинки и аудио отдаются через /media/
```

## Данные
- `vocab`: **Topic → Word**, плюс `SortingSet` (наборы для «Сортировки») и `Fact` (факты для профиля).
  Тип темы задаёт «картинку» по умолчанию: эмодзи, цифра (числа) или цветной круг (цвета).
  Поле `family` у темы не даёт «Найди лишнее» смешивать близкие темы (овощи и еда).
- `accounts.Profile.save_data`: **сохранение** аккаунта — один JSON-документ (формат ниже). Поля
  `updated`, `display_name`, `avatar` — копии из сохранения, чтобы их было видно в админке.

## Где живёт логика
- **Сервер** рендерит страницы, которые не зависят от игрока, отдаёт словарь (`/content.json`),
  собирает офлайн-снимок, регистрирует и хранит сохранения аккаунтов.
- **Клиент** (`static/js/app.js`): окно входа, сохранение и его синхронизация (`ZB.Save`),
  статистика из сохранения (опыт, серия дней, выученные и трудные слова, ответы по дням), «Слово дня».
  `static/js/games.js` — шесть игр и режим «Трудные слова» («Выбери перевод» по словам с ошибками,
  слово уходит из трудных после трёх верных ответов подряд). Каждая строит раунды из словаря, копит ответы и записывает их
  в сохранение одним действием, когда игра пройдена до конца.
- **Flutter** (`mobile/lib/`): `bundle.dart` — выбор активного снимка, чтение файлов и обновление;
  `bridge.dart` — функции телефона для JS; `main.dart` — заставка с обновлением снимка, WebView и
  перехват запросов.

## Офлайн-снимок
`manage.py build_bundle` рендерит все страницы через тестовый клиент Django, добавляет статику
(в проде — файлы с хэшем от collectstatic) и медиа слов. Результат:

```
manifest.json   {"version": "<хэш содержимого>", "built": <мс>, "files": {"/learn/": {"sha", "type", "size"}}}
blobs/<sha256>  содержимое файла
```
Версия зависит только от содержимого. Если пересобрать снимок без изменений, получится та же версия,
и телефоны ничего не качают. Приложение качает только блобы, которых у него нет,
проверяет sha256 и последним атомарно пишет манифест. При запуске выбирается снимок с бо́льшим `built`:
скачанный или из APK. Затем, до показа WebView, приложение проверяет обновление (манифест — не дольше
5 с, всё обновление — не дольше 20 с) и сразу включает новую версию. Если не успело — оно включится
при следующем запуске: во время игры страницы не меняются.

## Вход, сохранение и синхронизация
Схема: [client-server.mmd](client-server.mmd) (открывается в https://mermaid.live).

**Вход обязателен.** Пока на телефоне нет аккаунта (`zb.auth.v1`), поверх страниц открыто окно
регистрации или входа. Первый вход — только с интернетом: без сети окно пишет «Для первого входа
нужен интернет». Гостевого режима нет.

**Сохранение** — один JSON-документ на аккаунт:
```json
{"v": 2, "updated": 1760500000000,
 "profile": {"name": "Аня", "avatar": "🦊"},
 "words": {"17": {"ok": 3, "bad": 1, "seen": 2, "last": 1760500000000}},
 "days": {"2026-10-15": {"ok": 12, "bad": 3, "seen": 5}},
 "games": {"choose": {"ok": 20, "bad": 4, "played": 3, "best": 3}}}
```
Ключи `words` — id слов (seed сохраняет их стабильными), `days` — ответы и просмотры по дням (из них
серия 🔥, график и «дней занятий»), `best` — лучшие звёзды в игре. Токен и настройки устройства
(звук, уведомления, геолокация) в сохранение не входят: `zb.auth.v1` и `zb.settings.v1`.

**Стандартный цикл запуска:** снимок (`/bundle/manifest.json` и новые блобы) → синхронизация
сохранения → главная. Синхронизация: `GET /api/save` (тайм-аут 5 с) и сравнение `updated`. Если
локальное от того же момента или новее — `PUT /api/save`; если на сервере новее — серверное заменяет
локальное. Победитель заменяет проигравшего целиком, без слияния; если играть в один аккаунт на двух
телефонах без сети, более старое сохранение перезапишется. Без сети используется локальное.

**Конечные действия** (игра пройдена, карточки темы просмотрены, профиль изменён) меняют сохранение
через `ZB.Save.commit`: `updated = сейчас`, запись в localStorage и копию во Flutter, сразу `PUT`.
Сервер принимает `PUT`, только если `updated` не меньше хранимого, иначе отвечает `409` со своим
сохранением, и телефон принимает его — так два устройства не затирают друг друга в гонке.
Прерванная игра прогресс не меняет.

Переход со старой версии: журнал событий `zb.state.v1` (и его копия `progress.json` во Flutter)
сворачивается в сохранение на телефоне, а на сервере миграция `accounts/0005` сворачивает
`play.Attempt` тем же способом.

Токен — подписанный id пользователя (`django.core.signing`), cookies и CSRF не нужны.

Ключевые файлы: `backend/static/js/app.js`, `backend/static/js/games.js`, `backend/play/api.py`,
`backend/play/management/commands/build_bundle.py`, `mobile/lib/bundle.dart`, `mobile/lib/main.dart`.
