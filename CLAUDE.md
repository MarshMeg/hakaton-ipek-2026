# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

«Вотэс» — a Duolingo-style game for children learning the Udmurt language, built for the
«Удмуртский ИТ-класс „Вотэс“» hackathon (mobile track). All UI text, comments, commit messages and
docs are in **Russian**; keep it that way. Deadlines and the feature roadmap are in `ROADMAP.md`;
judging criteria that drive priorities are summarized there.

Architecture in one line: a **server-rendered Django app** (HTMX + Alpine.js + Tailwind) is the whole
game; the **Flutter app in `mobile/` is only a WebView wrapper** around it. Game logic never lives in Dart.

## Commands

All tooling goes through **mise** (mandatory; see `LOCAL_SETUP.md`). Configs are split so each part
installs only what it needs: `backend/mise.toml` (Python 3.12, Tailwind CLI, auto-venv `backend/.venv`),
`mobile/mise.toml` (Flutter 3.47, Java 17), root `mise.toml` (Docker tasks only). Never use the system
Python/pip; run commands via `mise run <task>` or `mise exec -- <cmd>` from the relevant directory.

Backend (run from `backend/`):

```bash
mise install && mise run setup                          # venv, deps, migrate, seed (seed is idempotent)
mise run dev                                            # runserver 0.0.0.0:8000
mise run test                                           # pytest (settings in pyproject.toml)
mise run test -- tests/test_answer_check.py::test_check_answer   # single test
mise run lint                                           # ruff check + format --check + migrations check (as CI)
mise run fmt | css | seed                               # format / rebuild app.css / reload course (--reset)
```

Without `DATABASE_URL` the app uses SQLite; without `USE_S3=1` media goes to `backend/media/`.

Full stack: `mise run up` (= `docker compose up --build`) from the repo root (web on :8000, MinIO console on :9001,
admin `admin`/`admin12345`). `backend/entrypoint.sh` runs `migrate`, `seed` and `createsuperuser` on every start.
`backend/Dockerfile` installs Python via mise from `backend/mise.toml` (`MISE_DISABLE_TOOLS` skips Tailwind)
and runs everything through `mise exec`, so the image and local dev use the same Python.

CSS: `backend/static/css/app.css` is **compiled and committed**. After adding Tailwind classes to
templates, rebuild it with `mise run css` (standalone Tailwind CLI v3.4.17, no Node; it scans only
`backend/templates/`). Classes not present in the compiled CSS silently do nothing.

Mobile (`cd mobile && mise run setup | check | dev | apk`; Android SDK comes from Android Studio,
not mise; CI builds the APK): only `lib/`, `test/`, `pubspec.yaml` and
`android/app/src/main/AndroidManifest.xml` are committed — the rest of `android/` is generated by
`flutter create --platforms=android --org ru.votes .` (`mise run setup`). Keep `mobile/test/widget_test.dart` in the repo:
otherwise `flutter create` generates a default test referencing `MyApp` and `flutter analyze` fails.

## CI/CD (`.github/workflows/`)

`ci.yml` runs on every push and PR: ruff, migrations check, pytest. `android.yml` runs only when
`mobile/**` or the workflow itself changes (plus manual `workflow_dispatch`): `flutter analyze`,
`flutter build apk`; on `main` its `release` job publishes a GitHub Release `apk-<run_number>` with
`votes.apk`. Backend-only changes don't produce a new APK. The stable download link is
`releases/latest/download/votes.apk`. The server URL baked into the APK is
`vars.SERVER_URL || https://hakaton.marshmeg.ru` (also the Dart default in `mobile/lib/main.dart`).

## Backend architecture

Three Django apps under `backend/`:

- `courses` — content only: `Course → Unit → Lesson → Exercise`, edited via Django Admin or loaded
  from `seeds/content.yaml` by `courses/management/commands/seed.py`. `Exercise.kind` is one of
  `choice | type | assemble | match`, and the meaning of `answer`/`options` depends on the kind
  (documented on the model and at the top of `content.yaml`). Multiple accepted answers are separated by `|`.
- `learning` — playing a lesson.
  - `services/lesson_engine.py` holds the lesson run **in the Django session** (`lesson_run`: queue
    of exercise ids, position, hearts, xp, mistakes, `answered` flag). Wrong answers cost a heart and
    re-queue the exercise once; XP is only for first-try correct answers; `finish()` writes
    `LessonResult` and calls `Profile.register_activity()` (XP + streak).
  - `services/answer_check.py` — answer normalization and the Udmurt-specific verdict: the five
    extra letters **Ӝ Ӟ Ӥ Ӧ Ӵ** typed as plain Cyrillic (ж з и о ч) give `ALMOST`, not `WRONG`.
  - `views.py` — HTMX flow: `lesson_answer` (POST) and `lesson_next` (GET) both re-render
    `templates/learning/partials/lesson_body.html` into `#lesson-body`; finishing returns an
    `HX-Redirect` to the result page. Non-HTMX requests fall back to full pages/redirects.
    Option order is shuffled with a seed of `(exercise.id, pos)` so it doesn't change after answering.
- `accounts` — `Profile` (xp, streak, `is_guest`). `accounts.services.get_player()` silently creates
  and logs in a guest user for anonymous visitors; every game view calls it. Signup converts the
  guest in place (renames + sets password) so progress is kept.

Templates: each exercise kind has its own partial in `templates/learning/partials/exercises/`;
client-side interaction (tile assembly, pair matching, the on-screen Udmurt letter keyboard) is
Alpine.js inline in those partials. `match` is validated on the client and auto-submits `answer=ok`;
the server always treats it as correct. Adding a new exercise kind means: a `Kind` choice, handling
in `lesson_engine.submit`, a partial, and a branch in `lesson_body.html`.

Game balance (hearts, XP) is in `settings.GAME`. Brand colors/fonts are tokens in
`backend/tailwind.config.js` (mirrored as constants in `mobile/lib/main.dart`). Fonts, htmx and Alpine
are vendored in `backend/static/` (no CDNs — the font must contain the Udmurt letters).

Media uses `django-storages` S3 backend against MinIO when `USE_S3=1`; public URLs come from
`S3_PUBLIC_DOMAIN`/`S3_PUBLIC_PROTOCOL` (behind HTTPS, `/votes-media/` must be proxied to MinIO).

## Content caveat

The seed vocabulary is demo content and must be verified by a native speaker before submission
("контент соответствует действительности" is a judging criterion). Don't invent new Udmurt words
or phrases without flagging them as unverified.
