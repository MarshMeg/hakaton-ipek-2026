# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

«Ӟеч-а бур-а удмурт кыл?» (team «Вотэс») — an app for children 5–10 learning Udmurt, built for the
«Удмуртский ИТ-класс „Вотэс“» hackathon (mobile track) by the customer's spec: main menu Обучение /
Игры / Профиль / Настройки, word cards by topic, six games, stats/report, **must work offline**,
Android 8.0+. All UI text, comments, commit messages and docs are in **Russian**; keep it that way.
Deadlines and the roadmap are in `ROADMAP.md`.

Architecture in one line: Django renders **player-independent pages** (Alpine.js + Tailwind); **game
logic and progress live in client JS** (`backend/static/js/`); `manage.py build_bundle` snapshots the
site into an **offline bundle** that the **Flutter WebView wrapper** (`mobile/`) serves from APK assets
by intercepting requests. Game logic never lives in Dart; Dart only serves the bundle, updates it and
exposes phone features to JS.

## Commands

All tooling goes through **mise** (mandatory; see `LOCAL_SETUP.md`). Configs are split so each part
installs only what it needs: `backend/mise.toml` (uv, Tailwind CLI; uv installs Python 3.12 per `backend/.python-version` and the deps into `backend/.venv`),
`mobile/mise.toml` (Flutter 3.47, Java 17), root `mise.toml` (Docker tasks only). Never use the system
Python/pip; run commands via `mise run <task>` or `mise exec -- uv run <cmd>` from the relevant directory.
Dependencies live in `backend/pyproject.toml` + `backend/uv.lock` (change them with `uv add`/`uv remove`,
commit both); there are no `requirements*.txt`.

Backend (run from `backend/`):

```bash
mise install && mise run setup                          # uv sync, migrate, seed (seed is idempotent)
mise run dev                                            # runserver 0.0.0.0:8000
mise run test                                           # pytest (settings in pyproject.toml)
mise run test -- tests/test_api.py::test_sync_is_idempotent_union   # single test
mise run lint                                           # ruff check + format --check + migrations check (as CI)
mise run fmt | css | seed | bundle                      # format / app.css / seed --update / snapshot → mobile/assets/bundle
```

Without `DATABASE_URL` the app uses SQLite; without `USE_S3=1` media goes to `backend/media/`.

Full stack: `mise run up` (= `docker compose up --build`) from the repo root (web on :8000, MinIO console on :9001,
admin `admin`/`admin12345`). `backend/entrypoint.sh` runs `migrate`, `seed`, `build_bundle` and `createsuperuser` on every start.
`backend/Dockerfile` is `python:3.12-slim` + the uv binary; it runs `uv sync --locked --no-dev` and puts
`/app/.venv/bin` on `PATH`, so the image and local dev use the same locked dependencies.

CSS: `backend/static/css/app.css` is **compiled and committed**. After adding Tailwind classes,
rebuild it with `mise run css` (standalone Tailwind CLI v3.4.17, no Node; it scans `backend/templates/`
and `backend/static/js/`). Classes not present in the compiled CSS silently do nothing.

Mobile (`cd mobile && mise run setup | check | dev | apk | apk:ask`; Android SDK comes from Android Studio,
not mise; CI builds the APK): only `lib/`, `test/`, `pubspec.yaml`, `assets/icon/`, `assets/bundle/**/.gitkeep`,
`android/app/src/main/AndroidManifest.xml` and `android/app/build.gradle.kts` (minSdk 26, desugaring for
`flutter_local_notifications`) are committed — the rest of `android/` is generated by
`flutter create --platforms=android --org ru.marshmeg --project-name hakaton .` (`mise run setup`; it doesn't overwrite existing files).
The Android application id and namespace are `ru.marshmeg.hakaton` (the Dart package is still `votes`); `--project-name hakaton`
makes `flutter create` put `MainActivity.kt` into that package. A stale `android/app/src/main/kotlin/ru/votes/` from an older
setup can be deleted.
The bundle in `mobile/assets/bundle/` is generated (`cd backend && mise run bundle`), not committed.
The launcher icon is `mobile/assets/icon/*.png` (rendered from the `.svg` next to them);
`dart run flutter_launcher_icons` (in `mise run setup` and in CI) writes it over the default Flutter icon.
Keep `mobile/test/widget_test.dart` in the repo: otherwise `flutter create` generates a default test
referencing `MyApp` and `flutter analyze` fails.

## CI/CD (`.github/workflows/`)

`ci.yml` runs on every push and PR: ruff, migrations check, pytest. `android.yml` runs when
`mobile/**`, `backend/**` or the workflow changes (plus manual `workflow_dispatch`): builds the offline
bundle (`DJANGO_DEBUG=0`, seed, collectstatic, `build_bundle --out ../mobile/assets/bundle` — same as the
server, so bundle versions match), then `flutter analyze`, `flutter build apk`; on `main` its `release`
job publishes a GitHub Release `apk-<run_number>` with `votes.apk` and `votes-ask.apk`
(`--dart-define=ASK_SERVER_URL=true`: asks for the server address on every launch, for testing against
another server; the bundle is then served under that origin). The stable download link is
`releases/latest/download/votes.apk`; the baked-in server URL is `vars.SERVER_URL || https://hakaton.marshmeg.ru`.

Deploy: the `deploy` job in `ci.yml` (push to `main`, after `backend` passes) rsyncs the sources to
`/opt/votes` on the server (`vars.DEPLOY_USER@vars.DEPLOY_HOST`, key in `secrets.DEPLOY_SSH_KEY`) and runs
`docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`, then curls
`vars.DEPLOY_URL/content.json`. `docker-compose.prod.yml` adds Caddy (`deploy/Caddyfile`: HTTPS,
`/votes-media/*` → MinIO) and unpublishes the web/MinIO ports. The server's `/opt/votes/.env` is not in
git and is excluded from rsync. The prod overlay sets `DJANGO_HTTPS_ONLY=1` (Secure cookies + HSTS).
The MinIO image is `pgsty/minio` (the official `minio/minio` was removed from the registries).
The production DB still holds tables of the removed `courses`/`learning` apps (and the
`learning_player_xp` view); they are orphaned and unused. `accounts/0004` moves `User.first_name`
into `Profile.display_name` and drops the old game fields. The stable download link is
`releases/latest/download/votes.apk`. The server URL baked into the APK is
`vars.SERVER_URL || https://hakaton.marshmeg.ru` (also the Dart default in `mobile/lib/main.dart`).

## Backend architecture

Three Django apps under `backend/`:

- `vocab` — content: `Topic → Word` (+ `SortingSet` for the sorting game, `Fact` for the profile),
  edited via Django Admin or loaded from `seeds/vocab.yaml` by `vocab/management/commands/seed.py`.
  Seed upserts by topic slug and (topic, udm), so **word ids stay stable** — progress events reference
  word ids. Topic `kind` (words/numbers/colors/phrases) decides the fallback "picture" (emoji, digit,
  colour swatch); `family` keeps related topics apart in «Найди лишнее». `content.py` builds
  `/content.json`, the single document all games read.
- `play` — pages (`views.py`: home, games, game, profile, settings, report — all player-independent,
  no CSRF tokens/user data in HTML, tested in `test_pages.py`), `/media/` passthrough from storage,
  `/bundle/` (serves `BUNDLE_DIR`), the cloud JSON API (`api.py`: signup/login/sync with a signed
  Bearer token, csrf-exempt; sync = idempotent union of events by uuid), `Attempt` (event log) and
  `management/commands/build_bundle.py` (renders every page via the test client + static + media into
  `manifest.json` + content-addressed `blobs/<sha256>`; version = hash of content only).
- `accounts` — `Profile` with the child's display name/avatar for the cloud account.

Client (`backend/static/js/`, plain ES2017 for Android 8 WebViews, loaded before Alpine):
`app.js` — `ZB.Store` (state in localStorage `zb.state.v1`: profiles, append-only event log
`{id,p,w,g,c,t}`, settings; backed up to Flutter via `ZB.Bridge`), `merge`, stats, word of the day,
sync/login/signup, sounds; `Alpine.store('app')` exposes profile/stats/settings to templates.
`games.js` — the six games as `Alpine.data` components sharing `base()`. Adding a game means: an entry
in `play/games.py`, a component in `games.js`, a partial in `templates/play/games/<slug>.html`.

Mobile (`mobile/lib/`): `bundle.dart` (active snapshot = newer `built` of APK assets vs downloaded;
background update downloads missing blobs, verifies sha256, writes manifest last; applies on next
start), `main.dart` (InAppWebView with `shouldInterceptRequest` serving GETs for the server origin
from the bundle; `/api/`, `/admin/`, `/bundle/` go to the network), `bridge.dart` (JS handlers:
`backup`, `restore`, `info`, `setNotifications`, `location`, `share`).

Brand colors/fonts are tokens in `backend/tailwind.config.js` (mirrored in `mobile/lib/main.dart`).
Fonts and Alpine are vendored in `backend/static/` (no CDNs — offline, and the font must contain the
Udmurt letters).

Media uses `django-storages` S3 backend against MinIO when `USE_S3=1`, but pages and `/content.json`
always link media as `/media/<name>` (served by `play.views.media`), so the same URLs work online
and inside the bundle.

## Content caveat

`seeds/vocab.yaml` comes from the customer's «Материалы к кейсу» (order normalized to udm — ru;
known issues are in `needs_check`). It still must be verified by a native speaker before submission
("контент соответствует действительности" is a judging criterion), as must the facts. Don't invent
Udmurt words, phrases, topic titles or UI praise in Udmurt without flagging them as unverified.
